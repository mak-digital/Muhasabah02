# Architecture

Layers:

- `lib/domain/` ? DailyCheckIn, PersonalResponse, analytics, recognition, copy
- `lib/data/` ? JSON codecs, Hive boxes, in-memory repositories for tests
- `lib/application/` ? Riverpod providers
- `lib/presentation/` — screens and shared UI (`domain_visual.dart` family/wash; `domain_line_icon.dart` outlined domain mark, not a score)
- `lib/features/` ? compatibility exports for earlier milestone paths

Persistence:

- Hive box `muhasabah_checkins_v5` — one JSON document per day (`dateKey`); record `schemaVersion` **6**
- Hive box `muhasabah_responses_v1` ? one JSON document per Response
- Hive box `muhasabah_domain_actions_v1` — one JSON document per user-listed domain action (Salah and Qur’an Home; scoped by domain)
- Hive box `muhasabah_dev_feedback_v1` — one JSON document per developer note, plus `__next_serial`. The notes register can permanently delete selected notes before download.
- Hive box `muhasabah_practice_hadith_v1` — the person’s Hadith to learn & practice register (catalog id, date added, source, content, Arabic, transliteration, translation, topic, Learning / Learnt / Practicing / Living it or Habit). Not a daily check-in field.
- Hive box `muhasabah_prefs_v1` — sample-data flags, first-look door acknowledgement (same `applicationReflectionAcknowledged` flag), first-day-of-week, display calendar, visible domains, personal mix, quotation cadence, the reflection quote the person stopped on for the current day or week, baselines, aspirations, weekly journal text, Hadith memorisation focus, optional Salah activity colours, and optional app lock
- Corrupt documents are isolated; healthy records remain readable
- Failed writes restore the previous document when possible

DailyCheckIn schema version: **6**. Recordable field count: **10**. Tahajjud, Ishraq, and Salat At Tawbah keep ternary fields and also store `activities['salah.tahajjud']` / `activities['salah.ishraq']` / `activities['salah.tawbah']`; they stay off the recordable count. Response schema version: **1**. Ontology metadata version: **3** (read-only activity and factor classification of existing persisted IDs; not a persistence schema). Raw activity IDs are catalog-local, not globally unique; the stable ontology key is `catalog:persistedId`. HomeTrace keys, including retired `family.*` and retired `hajj.preparation`, are not renamed. Zakat remains the existing DailyCheckIn standing status. Hajj standing, journeys, travelers, readiness, sources, learning states, and after-Hajj records live in Hive box `muhasabah_hajj_v1` as one JSON document (`current`) with `schemaVersion` **1**. Hajj Home is an offline planning dashboard on that store. Additive Phase 3A/3B fields (`planning`, return scenarios, milestone `templateId`, `onlineAssist`, `pendingProposals`) stay on schemaVersion 1. Suggested pathway dates are planning estimates; official deadlines are only those the person typed. Hajj online assistance is an on-device demonstration catalog behind two revocable consents; it is not a live eligibility or booking service. Pre-launch installs discard AppPrefs `hajj_status` without migrating it.

Sample/demo records use `synthetic: true` on check-ins and responses. They are not written at process start. The first-look door (`FirstLookDoorScreen`) asks once: quiet week (`clearFrom` if any synthetic rows exist) or `SyntheticCheckInSeeder.generateInto`. Both paths set `sampleSeeded` so auto-seed never runs later; quiet week does not set `sampleRemovedByUser`. Completing the door sets `personalMix` to `firstLook`. Unset mix still decodes to Same as Domains. Sample days include Qur?an context clusters so 30- and 90-day Recognition can show descriptive patterns (not causes). Settings ? Developer can still recreate, remove, or restore sample data.

Home week grids (`SalahHomeCard`, `QuranHomeCard`, `OptionalDomainHomeCard`) sit in a session-only Home domain stage (one week card at a time; fixed previous/next chevrons; count pills are not a score). After the stage, every shown domain Home lists Learn & Practice (Salah grouped like Home; Qur’an and Hadith as browse catalogs; Dhikr through Charity grouped like Home), then listed actions (collapsed by default; at most five full-width active rows with up/down order; register Active then Closed) and a local developer-note wash (collapsed; + add Note). Qur’an Home shows the three duration rows under one wash (ENGAGEMENT with Qur’an) and lists **Qur’an to learn & practice** as a Hadith-style browse catalog of widely used verses (own AppPrefs index). Recognition, Ponder, Recorded days, Noticed This Week, and Patterns Noticed are not on Home. Today?s full check-in uses the same stage over `orderedVisibleDomains` (mix first; session-only; chrome pinned). Progress calendars read `AppPrefs.firstDayOfWeek`, `AppPrefs.displayCalendar`, and `AppPrefs.visibleDomains` for presentation only. Date keys remain Gregorian `YYYY-MM-DD`. Unset prefs decode to `kBasicDhikrVisibleDomains` (six domains). Hajj is opt-in; standing status is AppPrefs, and daily preparation is `homeTraces`. Hidden domains are omitted from Home, Review Progress, and today?s check-in; stored records are not rewritten. The Review tab shows a period snapshot, a domain-colour mosaic that opens the same Progress calendars, then Look closer (Recorded days as a compact week grid and Recognition), Ponder, and Add a response. Historical Reflection for a saved day uses domain wash bands with tight name/state rows and a single Add a response control. Manage past check-ins lists saved days in compact week groups with an All/30/90 view filter; tap opens the editor, and ? or long-press can remove the app record. Settings ? Application ? Domains offers **All domains** and **Salah, Qur?an & Dhikr** (Hadith & Living Sunnah, Rights of Others, and Charity) presets; Knowledge, Time, Health, Wealth, Ummah, Character & Morals, and Fasting are not on the latter preset; checkboxes still allow a custom set. **Personal mix** (`AppPrefs.personalMix`) lives on the same Domains screen (shown domains, then this season?s mix). Salah Home cells for today and earlier days open that date?s Salah entry with the tapped band expanded (Obligatory Salah, Friday Prayer, or Voluntary Prayers); past days start locked until Edit, then Save. Future Salah cells are inactive. Qur?an Home shows a four-row Journey matrix (Practical relevance, Reflection, Understanding, Engagement): colour is the group when activity colours are on, letter is L2; tap records that row via a sheet (that group, None, or No answer recorded, then L2 plus No activity and No answer recorded). No answer recorded clears every stored item in that row; No activity records the row as not done. The title opens the focused check-in. Qur?an 7-day Progress uses the same Journey board (group rows ? weekday columns); cell tap opens the Journey sheet. 30-day and 90-day Qur?an Progress keep one calendar per stored dimension, titled as the Home Journey groups, and open the focused check-in on that dimension?s band. Optional-domain Home and Progress cells open that date?s focused entry with the tapped band expanded and other bands collapsed; the selected date is shown on the entry. Optional domain rows are stored in `homeTraces` on DailyCheckIn schema **6** and do not count toward `recordableFieldCount`. Dhikr traces include post-fard Salah adhkar (`dhikr.postFardFajr` – `dhikr.postFardIsha`), morning/evening, and other remembrance (`dhikr.generalDhikr`, `dhikr.gratitudeDhikr`, `dhikr.travelDhikr`, `dhikr.personalDhikr`, `dhikr.otherAdhkar`). Other Adhkar rows may also store additive `dhikrContext` lists of activity responses (schema v6 JSON, off the recordable count) without converting legacy unanswered ternary marks. Dhikr Home uses a full item?day week like Akhlaq (title opens check-in). Knowledge, Time, Health, Wealth, Ummah, Fasting, and Hajj Home weeks use a full item?day matrix like Akhlaq when those domains are shown (title opens check-in). Full check-in edits those same rows with later bands collapsed until opened; Other observations sit after domain cards. Review opens `OptionalDomainProgressScreen` for Dhikr, Akhlaq, Rights of Others, Knowledge & Beneficial Speech, Time & Barakah, Physical Health & Energy, Wealth & Stewardship, Ummah, Fasting, Charity, and Hadith. Home, check-in, Review, and Historical Reflection place Hadith & Living Sunnah immediately after Qur?an Engagement. Hadith Home is four rows: ENGAGED with Hadith (Read and/or Listened), Retention (Memorization/Revision), Learning (Study Circle/Discussion), and Lived / Noticed (Lived /Noticed others). Duration twins of Qur’an Engagement apply to the first three. Retired eight-row keys stay stored and are not migrated. Akhlaq, Rights of Others, Knowledge, Health, Wealth, Ummah, and `hadith.livedNoticed` traces do not store helping/distracting factors. Time & Barakah V1 stores a four-state primary observation in `activities['time.t01']`–`time.t08` (and mirrored `homeTraces`) with optional context/outcome/note in `homeTraceFactors` for that key; generic helping/distracting factor lists stay hidden. Historical Reflection still reads retired `akhlaq.guardedMyGlance` marks. Retired Time Presence/Trust/Rest keys are classified in ontology only and are not shown. Optional-domain cell sheets may store `homeTraceFactors` for other domains. Charity traces use `CharityFactorCatalog` (one Giving and Care helping/distracting catalog) rather than the Qur?an context list. Check-in may store `situationNotes`. Neither is treated as a cause.

Hadith **Hadith to learn & practice** is a built-in catalog in `practice_hadith_catalog.dart` plus a local Hive register `muhasabah_practice_hadith_v1` (date added, source, content, topic, Learning / Learnt / Practicing / Living it). Browse index is AppPrefs. It is not a daily trace or a grade.

Qur’an **Qur’an to learn & practice** is a built-in catalog in `practice_quran_catalog.dart` stored in the same register, filtered by domain `quran`. Browse index is `AppPrefs.practiceQuranBrowseIndex` (not shared with Hadith). It is not a daily trace, khushu’ score, or hifz grade.

`noticedPatterns` looks at the last 90 days of engagement marks. It can emit weekday clustering, weekend clustering, or appearance across multiple weeks. It does not emit improved/declined/better/worse language. View evidence lists the engagement dates.

Reflection quotes are selected with a calendar bucket (`day` or `day ~/ 7`) and domain rotation. User records are not an input. Hidden cadence removes the Home card. Open citation loads the public https page (quran.com or sunnah.com) in an in-app reader with Close and Share; Qur’an Play recitation uses a public 128 kbps audio file in the app (not the page’s WebView player) so the sound stays clear; Open in browser remains a fallback. Records are not sent. Learn & Practice Arabic uses AppPrefs `arabicScriptFace` and `arabicScriptSize`.

Baselines store engagement / not-done / unanswered day counts per row. They do not store percentages, scores, or achievements.

Approved Qur?an same-day dependency (the only automatic write):

| If Recorded engagement | Recitation | Recitation with Meaning | Other Qur?an rows |
| --- | --- | --- | --- |
| Recitation with Meaning | Auto-fill engagement | ? | Independent |
| Recitation | ? | Independent | Independent |
| Memorisation, Revision, Tafsir, Qur?anic Reflection, Conscious Application | Independent | Independent | Independent |

While Recitation with Meaning is engagement, Recitation cannot be set to unanswered or recorded as not done. Application Reflection is not in this matrix.

Recognition patterns are computed from stored Qur?an peer-dimension outcomes and optional context factors. They are not persisted. Personal Response provenance may snapshot the legacy `RecognitionPattern.identity` (`domain+subject+outcome+question+factorId`). Copy-independent definition identity is `RecognitionDefinition.stableId`: `recognition:<domain>:<subject>:<outcome>:<factorStableId>`. The 30-day / 90-day window is evaluation metadata, not part of that id. Counts and supporting dates are occurrence evidence. Reading and Application Reflection are not Recognition subjects.

Marks Guide copy lives in `lib/presentation/home/marks_guide_sheet.dart`. FAQ clarifications live in `lib/domain/faq.dart`. Qur?an factor catalogs are in `lib/domain/context_catalog.dart`. Salah factor lists are prayer-relevant in `lib/domain/salah_factors.dart`.
